层级与导航改动（三套共用）

  • 常驻左导航取代右上角三个孤立图标：专注 / 日程 / 报告 / 设置，选中态有 2px 语义色标记，新增模块只需加一项
  • 主窗只回答两件事：这一轮在做什么、今天做了多少；最近完成在 ≤500×640 自动折叠（沿用现有垂直预算分档）
  • 抽屉覆盖而非挤压：导航始终可见，主区降饱和度作反馈，避免小窗下主内容被挤没
  • 统一反馈：按压 scale .97、焦点 2px 描边、toast、空态与加载态共用一套组件；无 ripple，尊重减弱动画

三处架构冲突与隔离方案

冲突事实解法
色板全局耦合PineColors 是 static const，全仓 428 处直接引用，main.dart 一次性套到 MaterialApp新增桌面令牌作用域（ThemeExtension / InheritedTheme）挂在桌面外壳；桌面读新令牌，手机端继续读原 PineColors，零改动
抽屉内容同源_desktopDrawer() 直接嵌 StatsPage / SettingsPage / PlanPanel共用组件改为「先查作用域、无则回退原色板」，桌面抽屉自动跟随新视觉，不产生「新外壳 + 旧抽屉」
测试锁定stage_color_test 锁死 PineColors 对比度；desktop_layout_test 锁死 4 档窗口零滚动原 theme.dart 一字不改 → 色板测试不动；新布局沿用同一垂直预算分档，补跑布局回归

落地顺序（选定方向后）

  • ① 新文件 desktop_tokens.dart：三选一令牌 + 间距 / 圆角 / 动效常量（不动 theme.dart）
  • ② 共用组件取色适配层：widgets.dart / sheets.dart 加作用域回退
  • ③ 重写 home_page.dart 桌面分支：左导航骨架 + 主窗分区 + 抽屉
  • ④ 抽屉内三页跟随；统一空态 / toast / 焦点态
  • ⑤ dart analyze 零告警 + flutter test 全绿 + 4 档窗口零滚动 + 真机截图，分阶段提交推送
关于「只改 macOS」这个前提：双端同源架构下，换色板必然影响手机端，因此本提案采用「桌面专属令牌作用域」隔离——这也是后续手机端换新视觉时可直接复用的扩展点。 若你更希望「全局换肤、手机端顺带一起变」，实现更简单（直接改 theme.dart），但会超出本轮选定的范围，且与 stage_color_test 冲突，需要一并改断言。请在选方向时说明。
