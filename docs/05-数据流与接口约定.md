# 05 关键数据流与接口约定

> 本文所有字段名均取自当前代码（`models.dart` / `cloud_sync.dart` / `storage.dart` / `cloud_auto.dart` / `tencent-sync/src/index.js`）。
> 按代码核对：**2026-10-23**（v1.3.7+8）。网页端已冻结，`index.html` 不再作为 schema 的参考方。

## 1. 本地持久化（安卓/macOS）

| 项 | 值 |
|---|---|
| 存储 | `SharedPreferences` |
| 当前键 | `pine-pomodoro` |
| 旧版键（只读兼容） | `pomodoro_data` |

## 2. 计时状态机（`engine.dart`）

| 概念 | 说明 |
|---|---|
| 模式 | `SessionMode.focus / shortBreak / longBreak` |
| 会话 | `ActiveSession`（含 `deadline`、`overtimeStartedAt`、`running`、`targetReached`） |
| 视图 | `SessionView.of(data, now)`：`mode/running/targetReached/plannedSeconds/remainingSeconds/overtimeSeconds/elapsedSeconds/clockText/elapsedText/progress`（`clockText`=剩余或超时 `+MM:SS`，`elapsedText`=已累计 `mm:ss`/`h:mm:ss`） |
| 超时 | `targetReached == true` 即进入超时（含"已到点"），主卡转 `gold`，时钟显示 `+MM:SS` |
| 完成 | `complete()` 写 `FocusRecord`（**仅专注模式**），随后**按本次实际专注时长决定下一个休息**：`elapsedMinutes > 70` → `longBreak`，否则 `shortBreak`（2026-10-09 起，取代"每 4 次轮换"） |
| 丢弃 | `discard()` 清会话、不写统计 |
| 补记 | `addManual(taskName, minutes, at)` 写入 `RecordStatus.manual` |
| 统计 | `StatsView.of(data, now)`：`todayMinutes/todayCount/weekMinutes/streak/weekTaskTotals/totalForDay()/tasksInWeek()/maxDay()` |

**改 `engine.dart` 前必读**：
- 所有操作返回新对象（不可变更新），`complete()/discard()` 用 `copyWith(clearActiveSession: true)` 显式清会话。
- 超时锚点取 `deadline` 是历史 bug 的修复，有单测守护（`test/widget_test.dart`「计划时长到点后继续累计」），勿改回"取当前时间"。
- 休息类型**只看时长**（`view.elapsedMinutes > 70`），不要再引入次数轮换——两套口径并存正是 10-09 前的混乱来源。

**统计口径（2026-10-01 定稿，此后未变）**：
- **统计日分界 = 凌晨 3 点**：`dateKey()` 返回统计日键（0:00–2:59 归前一天）。记录 dayKey、今日清单、今日/本周/月历聚合统一使用；旧数据（自然日口径）不迁移。
- **番茄数 = 时长当量**：`pomodoroEquiv(分钟)`——每满 50 分钟 1 个，**缺口满 40 分钟进位**（`(m+10)~/50`：34→0、40→1、49→1、85→2）。
- **展示文案**：`formatMinutes` 不足 1 小时给「45 分钟」，整小时给「3 番茄」，含零头给「3.7 番茄」（一位小数）。
  `MinutesText`/`minutesRichSpan` 只负责排版（大数字 + 小单位 0.58×），**不参与取整**。
- **最近完成列表例外**：走 `formatHoursMinutes`（`1 小时 5 分钟`），四舍五入到分钟，不套番茄口径——
  单条记录用番茄当量读不出真实时长。

**切换模式 = 挂起（2026-09-09 起）**：`switchMode(data, mode, now)` 对进行中会话不再丢弃——运行中自动暂停冻结，切回原模式即 `resume` 继续；挂起期间 UI 显示新模式的待开始视图 + 金色提示条。挂起态点「完成」承接 complete 语义（按已专注时长落记录后自动休息）。

## 3. 云端同步接口（腾讯云 SCF）

Base URL：`CloudSync.defaultBaseUrl`（两端内置）。

| 方法 | 路径 | 请求 | 成功响应 | 冲突 |
|---|---|---|---|---|
| POST | `/sync/upload` | `{deviceCode, payload, baseUpdatedAt?}` | `{updatedAt}` | `baseUpdatedAt` ≠ 云端 → **409 `{conflict:true}`** |
| GET | `/sync/download?deviceCode=` | — | `{payload, updatedAt}` | 无备份 → 404 |
| GET | `/ping` | — | `{"ok":true,"provider":"tencent-scf","llmBound":bool,...}` | — |
| POST | `/plan/parse` | `{text}` 或 `{url}` | `{plan, lines, model, fromUrl, usage}`：`plan` 是「月/日<TAB>条目」文本 | 无密钥 → 501；抽不出 → 422；模型故障 → 502 |

超时：`CloudSync.timeout = 20s`。
同步码：`[A-Za-z0-9_-]{16,128}`，`CloudSync.generateDeviceCode()` 生成 28 位（去易混淆字符）。

## 4. 云净荷 schema（`AppData.toCloudMap()`）

```json
{
  "tasks":    [...],          // PineTask（含 name/color）
  "records":  [...],          // FocusRecord（含 taskName/minutes/dayKey/status/at/eventId?）
  "events":   [...],          // FocusEvent（id/name/taskName/startedAt/finishedAt/paused…）
  "todos":    {"YYYY-MM-DD":[...]},  // TodoItem（text/done）
  "settings": {...},          // TimerSettings（focus/short/long）
  "selected": 0,              // selectedIndex
  "goalMinutes": 200,         // 今日目标（分钟；旧字段 goalTarget 已迁移）
  "weekGoal": 20,             // 本周目标（次）
  "soundEnabled": true,
  "notifyEnabled": true
}
```

- 本机全量 `toMap()` = 云净荷 + `idleMode` + `activeSession` + `sync` + `countdown`（**同步状态、会话、考试倒计时都不上云**）。
- **`countdown` 刻意不上云**：网页端没有该字段，一旦由旧端回传，净荷里缺字段会把本机设置重置为默认（用户的考试名/日期丢失）。
- **合并规则**：`mergeFromCloud()` 对 `records` 与 `events` 都按 **id 并集**——
  云端独有补入、本机独有保留、同 id 云端优先；同 id 记录**保留本机 `eventId` 归属**
  （2026-10-05 事故：旧端净荷无 `events`，直接采用会把本机事件清空）。
- 网页端旧 schema（`tasks/records/history/done`）已不再需要考虑——网页端冻结。

## 5. 同步策略（`cloud_auto.dart`）

| 触发 | 行为 |
|---|---|
| 完成一次专注（`afterFocus`） | **必达**：不参与节流；若同步通道被占用则 `_pendingPushes++` 排队；失败同样留待补传 |
| 本机任意改动（`afterLocalChange`） | 20s 节流上传；409 冲突静默保留本机；**会话进行中不上传**（避免半截记录进云端） |
| App 启动 / 回前台 | 拉取对比；启动时在拉取之后补传上次退出前未上传的改动 |
| 每 3 分钟巡检 | 先推后拉（僵尸进程/常驻不重启用） |
| 上传冲突（409） | 转为拉取；两端都有改动 → **弹窗询问**；本机无改动 → 静默采用云端 |

> **历史坑**：`afterFocus` 原先有三处静默 `return`（`_busy` 竞争、15s 节流、失败无重试），
> 且 409 分支在 `_busy` 未释放时调 `_pull`（而 `_pull` 自带 `!_busy` 前置）——
> **"冲突弹窗"在 2026-10-12 之前从未真正执行过**。改这块务必跑 `test/cloud_auto_test.dart`。

**指纹机制**：`cloudFingerprint(data)` = 剔除每次恢复都会重新生成的 `id` 字段后的规范化 JSON。
它决定「本机自上次同步后是否有改动」（与 `sync.lastSyncedHash` 比较）。改动此算法必须同步更新
`test/cloud_auto_test.dart` 的回归用例（含 events 字段）。

## 6. 通知与前台服务（安卓）

| 项 | 值 / 行为 |
|---|---|
| 前台服务通知 id | `5150`（`ForegroundRunner._serviceId`） |
| 通知频道 | `pine_lock_timer`（「锁屏剩余时间」） |
| 锁屏倒计时 | `LockTimer` 用**系统 Chronometer** 渲染，进程被 ColorOS 冻结时仍走表 |
| 刷新时机 | 仅在状态切换（模式/运行/超时）时更新通知（`_syncForeground` 的 key 比较）；**禁止**改回每秒刷新 |
| 超时显示 | 从 `overtimeStartedAt` 累计 |
| 到点提醒 | 本地通知 + 三音提示音（`Notifier.alert/chime`），不依赖云端 |
| 通知小图标 | `@drawable/ic_notification`（Manifest meta-data `com.pine.pomodoro.service.NOTIFICATION_ICON`） |

## 7. 数据安全约定

1. 采用/恢复云端数据前自动写本机安全副本（`pine-safety-copy-*`，保留 3 份）。
2. 云端 409 永不静默覆盖本机；两边都有改动一律弹窗。
3. 云端备份不含：推送订阅、进行中的临时计时（`activeSession`）、同步状态（`sync`）、考试倒计时（`countdown`）。
4. 删除专注事件只删事件定义，历史 `FocusRecord` 保留（仅解除 `eventId` 关联）。
5. 记录改 `at` 时必须同步重算 `dayKey`（`updateRecord` 已实现），否则记录会留在错误的一天。

## 8. 会话实时镜像（2026-09-09 新增，方案 A：短轮询）

安卓 ↔ macOS 的「一边开始，另一边也开始」。**与备份通道完全解耦**：会话是瞬态，
走独立的 `session/{deviceCode}.json`（覆盖写，只留最新一份快照），不碰 `sync/` 备份。

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/session/publish` | `{deviceCode, deviceId, seq, session, taskName}`（session=null 表示已无会话） | `{seq, at}` |
| GET | `/session/poll?deviceCode=` | — | `{seq, deviceId, at, session, taskName}`；无记录/损坏 → 全空态（seq=0），**不返回 404** |

机制与约束：

- **快照即 `ActiveSession.toMap()`**，无新 schema；时间口径（`deadline`/`overtimeStartedAt`）为绝对时刻，信任两端系统时钟（NTP 秒级偏差对 3 秒轮询无感）。
- **seq 单调**：本机发布 = `已见最大 seq + 1`（seq 已改用 **epoch 毫秒**，避免两端各自计数撞号）；采纳判定 `shouldAdoptRemoteSession()`：seq 更大 **且** 非本机回声。后写者胜 → 双端同时操作天然收敛。
- **回环/乒乓抑制**：本端采纳远端状态时不再发布（`fromRemote` 标记）；发布前内容与上次相同则跳过。
- **统计只记一份**：谁端「完成」谁写 `FocusRecord` 并经备份同步到达对端；镜像端清会话不记账。
- **轮询节奏**：仅 App 前台轮询（空闲 30 秒 / 专注 3 秒自适应）；后台/息屏暂停，回前台立即收敛一次。手机息屏期间「不即时」是平台冻结限制（07 §4）。
- **额度**：自适应之后两个数量级都低于 SCF 免费额度（100 万次/月）；费用告警保持开启。
- **开关**：设置页「会话实时同步」（独立 prefs 键 `pine-session-mirror` + `pine-device-id`，不进云净荷），默认关，需已绑定同步码。
- 后端改动需 `deploy.py --update` 重新部署后生效。

## 9. 日程与待办（todos）

| 项 | 约定 |
|---|---|
| 结构 | `Map<String, List<TodoItem>>`，键 `YYYY-MM-DD`，值可空数组（本机历史里就有 10 个空键） |
| 日期键 | **自然日** `ymdOf(目标日)`。**刻意不套** `dateKey()` 的凌晨 3 点口径：日程是"哪天要做"，不是"算进哪个统计日" |
| 为什么 | 若用 `dateKey`，10/24 的 00:00–02:59 排"明天"会落到 `2026-10-23`（单测 `test/plan_import_test.dart` 钉住这条） |
| 导入 | `parsePlan()` 解析 `10/24`、`2026-10-24`、`#` 注释与非法行；`mergePlanIntoTodos()` **幂等**（同日同文本视为重复），保留原条目与勾选状态 |
| 合并策略 | `mergeFromCloud()` 对 todos 是**整体采用云端**（不是 id 并集）。records/events 能并集是因为它们只追加；待办可删改，并集表达不了删除 |
| 并发约束 | 因此待办是**单端编辑**：多端同时改时，后上传者覆盖前者。要改成并集必须单独立 ADR（需引入墓碑/删除标记） |
| 回写方式 | 面板回传「一次变换」（`TodosTransform`），父级用**最新** `_data` 套用；禁止用打开面板时的快照整份回写（会顶掉期间采纳的云端数据） |
| 云净荷 | 未来日期键原样上传/回传，老版本客户端不认日期也会原样保留——这是复用 `TodoItem` 而不是新增字段的决定性理由 |
