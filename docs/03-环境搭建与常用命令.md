### 2.2 构建 APK

**可直接在工作区内构建**，无需复制到 /tmp（2026-09-08 实测）：

```bash
# 全 ABI（约 53MB）
$F build apk --release

# 仅 arm64（约 19MB，推荐交付）
$F build apk --release --target-platform android-arm64
# 产物：build/app/outputs/flutter-apk/app-release.apk
```

> **构建必须能写 `~/.gradle`**：Gradle 9 的 wrapper 即使发行包已解压，也要先拿
> `gradle-x.y.z-all.zip.lck` 排他锁，随后写 `caches/`、`daemon/`。在只放行工作区写权限的
> 沙箱里，第一条就 EPERM，而 Flutter 会打印误导性的「Gradle threw an error while downloading
> artifacts from the network」——**那不是网络问题**，是文件权限。

安装到手机（USB 调试）：

```bash
tools/android-sdk/platform-tools/adb install -r pomodoro_app/build/app/outputs/flutter-apk/app-release.apk
```

### 2.3 构建 macOS 桌面版

**一条命令（推荐）**：`scripts/build-macos.sh` —— 它把「/tmp 副本 → 重建插件符号链接 →
清 DerivedData → `pod install` → 构建 → 归档 zip 到 `outputs/` → 安装到 `/Applications/pinecore.app`
→ 杀掉新旧实例并启动」串好了。

```bash
bash scripts/build-macos.sh
```

> 脚本原先放在 `outputs/build-macos.sh`，而 `outputs/` 是 gitignore 的——换机就失传，
> 2026-10-23 移入 `scripts/` 并入库。脚本内的路径仍指向本机 `~/Documents/Codex/...`，
> 换机后改头部变量即可。

手工步骤：

```bash
rsync -a --exclude build --exclude .dart_tool --exclude .gradle \
  ~/Documents/Codex/2026-08-13/pinecone/pomodoro_app/ /tmp/pine-macos/ && cd /tmp/pine-macos
export LANG=en_US.UTF-8
$F build macos --release
# 产物：build/macos/Build/Products/Release/pinecore.app   ← 2026-09-29 起产物名 = pinecore
#   名字来自 macos/Runner/Configs/AppInfo.xcconfig 的 PRODUCT_NAME；
#   改它必须同步改 project.pbxproj 的产物引用与 Runner.xcscheme 的 BuildableName，
#   否则 Xcode 找不到产物。（bundle id 不要动，动了偏好与本地数据全丢）
# 归档：zip 用 ditto -c -k --sequesterRsrc --keepParent
```

> **出包后必须退出正在运行的旧进程再打开新包**——App 常驻菜单栏（关窗不退出），
> 旧进程不退会一直跑旧代码，表现为「新功能没生效」。
> **Release 沙箱必须保持关闭**（`macos/Runner/Release.entitlements` 中
> `com.apple.security.app-sandbox = false`），本地 ad-hoc 签名 + 沙箱会触发
> `_libsecinit_appsandbox` 崩溃。悬浮窗/菜单栏相关雷区见 07 §4。
