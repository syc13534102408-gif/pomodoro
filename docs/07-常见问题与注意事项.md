# 07 常见问题与注意事项（雷区清单）

> 改代码前通读一遍。每条都踩过坑，多数有单测或事故记录。
> 最后核对：**2026-10-23**（v1.3.9+10）。

## 1. 依赖与构建

| # | 雷区 | 说明 |
|---|---|---|
| 1 | `path_provider_android: 2.2.23` override **勿删** | 2.3.x 引入 `jni` 原生模块，CMake 产物写回只读 pub 缓存导致构建失败 |
| 2 | `fl_chart` **禁止重新引入** | 统计图已由 `BrickBars` 自绘 |
| 3 | `flutter analyze` 会崩 | 本机 LSP 通道崩溃（exit 255），用 `tools/flutter/bin/dart analyze` 代替 |
| 4 | **遥测假失败** | `dart analyze` / `flutter test` 在受限环境会因删 `~/.dart-tool/dart-flutter-telemetry.log` 失败而在**成功之后** exit 1。判据看输出（`No issues found!` / `All tests passed!`），加 `--suppress-analytics` 可规避 |
| 5 | **`flutter build apk` 需要写 `~/.gradle`** | Gradle 9 wrapper 即使发行包已解压也要拿 `.zip.lck` 排他锁，再写 `caches/` `daemon/`。只放行工作区写的沙箱会在第一秒 EPERM，Flutter 却打印「error while downloading artifacts from the network」——**那不是网络问题** |
| 6 | 改名/搬目录后构建失败 | `flutter config --android-sdk/--jdk-dir` 与 `android/local.properties` 的 `sdk.dir` 都存绝对路径，必须重设 |
| 7 | release 用 debug 签名 | 当前 `build.gradle.kts` 显式如此（本地分发），上架商店前需换正式签名 |
| 8 | macOS Release 沙箱必须关闭 | `macos/Runner/Release.entitlements` 中 `com.apple.security.app-sandbox = false`；本地 ad-hoc 签名 + 沙箱会启动即崩 |
| 9 | macOS 新增 Swift 文件不会自动进工程 | 必须手改 `project.pbxproj` 四处：`PBXBuildFile`、`PBXFileReference`、Runner group `children`、target `Sources`；用 `xcodebuild -list` 验证 |
| 10 | 出包后必须**退出旧进程**再打开新包 | App 常驻菜单栏（关窗不退出），旧进程会一直跑旧代码，表现为"新功能没生效" |

## 2. 逻辑层（改前必读）

| # | 雷区 | 说明 |
|---|---|---|
| 1 | 超时锚点 | `overtimeStartedAt` 必须取 `session.deadline`，不是"现在"；改错会让后台经过的时间不计入超时（有单测） |
| 2 | 通知刷新 | 前台通知只在状态切换时更新，**不要**改回每秒刷新——会打断 Chronometer 走表 |
| 3 | 通知 id / 频道 | 锁屏倒计时与前台服务共用 id `5150`、频道 `pine_lock_timer`，发布即原地替换 |
| 4 | 同步指纹 | `cloudFingerprint()` 剔除 `id` 是为了防止"恢复后 id 变化"产生假冲突；改动必须同步更新 `test/cloud_auto_test.dart` |
| 5 | 自动同步前置条件 | 仅在**已绑定同步码**时工作，避免静默创建孤立备份 |
| 6 | **休息类型只看时长** | `elapsedMinutes > 70` → 长休，否则短休（2026-10-09 起）。**不要再引入 `count % 4` 轮换**——两套口径并存正是 10-09 前的混乱来源；有 `test/rest_rule_test.dart` 守 50/70/75/100 四个边界 |
| 7 | 两端同步地址 | 改 `cloud_sync.dart` 的 `CloudSync.defaultBaseUrl` 要同步改另一端的备份码/地址（网页端已冻结，不再涉及） |
| 8 | 会话镜像的回环抑制勿删 | 采纳远端必须带 `fromRemote: true`，发布前必须比对内容摘要（`_lastPublishedSessionJson`） |
| 9 | 镜像轮询只在 App 前台跑 | 息屏/后台轮询既被冻结也没意义；回前台必须立即补一次 poll |
| 10 | 镜像端不落记录 | 会话实时同步只搬**状态**；`FocusRecord` 只由发起端写入 = 统计翻倍风险 |
| 11 | `dateKey` 是统计日口径（凌晨 3 点分界） | 0:00–2:59 归前一天；任何比较"今天/周窗口"的代码必须走 `statDayOf`/`ymdOf`，禁止拿 `dayStart(now)` 直接配 `dateKey` |
| 12 | **番茄当量 40 分钟进位** | `pomodoroEquiv` = `(m+10)~/50`（2026-10-01 定稿）。展示走 `formatMinutes`（整小时/带零头给「N 番茄」，不足 1 小时给「N 分钟」）；**最近完成列表例外**，走 `formatHoursMinutes`（人话时长） |
| 13 | `switchMode` 是挂起语义 | 对进行中会话暂停冻结而非丢弃；改回 discard 语义会让用户切个模式就白干一轮 |
| 14 | 事件关联会悬空（2026-09-29 实际发生） | `FocusRecord.eventId` 指向**已删除的事件**时，`eventStatsOf` 按 id 相等求和 → 该记录在「事件进展」隐身（总统计不受影响）。**应用内修复**：记录详情 → 修改这条记录 → 归入专注事件（引擎会拒绝不存在的事件 id）。**预防**：改名用 `renameEvent`（id 不变），不要"删了重建" |
| 15 | **409 弹窗路径曾被 `_busy` 挡住** | 2026-10-12 之前，409 分支在 `_busy` 未释放时调 `_pull`，而 `_pull` 要求 `!_busy` → "冲突询问"从未执行。改动 `AutoCloudSync` 后必须跑冲突用例 |
| 16 | **完成专注是必达事件** | 上传失败/通道被占用只能排队（`_pendingPushes`），不能静默丢弃；`flushPending` 要在回前台、3 分钟巡检、启动时都被调用 |
| 17 | 会话镜像 seq 用 **epoch 毫秒** | 两端各自计数会撞号，导致对端更新被静默忽略（"Mac 已完成、手机仍显示进行中"的根因） |
| 18 | 记录改 `at` 必须重算 `dayKey` | `updateRecord` 已实现；绕过它直接 `copyWith` 会让记录留在错误的一天 |
| 19 | `setRecordEvent` 的护栏勿删 | 拒绝写入不存在的事件 id——写进去就是亲手制造悬空引用 |

|---|---|---|
| 1 | **不要用 API 网关** | 腾讯云 API 网关已于 2025-06-30 停服；本项目用 SCF「函数 URL」触发器 |

| 7 | **部署后配置可能没生效** | `UpdateFunctionCode` 后函数短暂 `Updating`，此时改配置会被拒；旧脚本只打印"配置跳过"，导致环境变量静默丢失（2026-10-23 真的踩到，`llmBound` 一直是 false）。脚本已加 5s×4 重试；部署后务必 `curl /ping` 看 `llmBound` |
| 8 | OpenCode Zen 的免费模型不能外部调用 | `*-free` 模型返回 403 `FreeTierError`（仅限官方客户端）；外部只能用付费模型，余额不足是 402 |
| 9 | `/plan/parse` 超时预算 | SCF 超时 20s，模型调用已设 12s 上限；提示词要求「只输出日期+条目」以压低输出长度，别再让它写解释 |

## 7. 面板与布局（2026-09-29 新增）

| # | 雷区 | 说明 |
|---|---|---|
| 1 | `_SheetScaffold` 自身不滚动 | 它是 `SafeArea → Padding → Column`，没有滚动容器。面板内容一长就会溢出，**必须自己给列表一个高度**（`SizedBox(height: ...)` + 内部 `ListView`），高度按屏幕封顶（本仓取 60%）。 |
| 2 | 别在 `mainAxisSize.min` 的 Column 里用 `Flexible` | min 尺寸下没有剩余空间可分，`Flexible` 会触发 `hasSize` 断言；要么显式高度，要么把 Column 改成 max。 |
| 3 | `AlertDialog` 里别用 `CrossAxisAlignment.stretch` + `Expanded` | 对话框按内在宽度测量（`RenderIntrinsicWidth`），与 stretch/Expanded 冲突；给 `content` 一个固定宽度（如 `SizedBox(width: 300)`）。 |
| 4 | 无 `flutter_localizations` | 系统日期/时间选择器是英文的；补记/修改记录沿用 `showDatePicker`/`showTimePicker` 与现有面板保持一致。 |
| 5 | **`AlertDialog` 里的 `TextField` 必须给有界盒子** | 对话框按内在尺寸测量，`TextField` 在里面高度会被算成天文数字（实测溢出 98050px）。用 `SizedBox(width:, height:)` + `Expanded(child: TextField(expands: true, maxLines: null))`，别让 `Column` 自由测量它。 |
| 6 | **对话框的 `TextEditingController` 归对话框自己** | `await showDialog(...)` 之后立刻 dispose 控制器，关闭动画还在用它 → `A TextEditingController was used after being disposed`。把它做成 StatefulWidget、在 `dispose()` 里释放。 |
| 7 | **`BrickButton` 不要放进 `AlertDialog.actions`** | 它内含 `LayoutBuilder`，`OverflowBar` 算内在高度时会崩。对话框按钮位置用 `TextButton`，颜色仍取 `PineColors.pine`。 |
| 8 | 待办只有**单端编辑** | `mergeFromCloud` 对 todos 整体采用云端；多端并发以后上传者为准（见 05 §9）。 |
| 9 | 桌面端 Stack 层级 | 抽屉后绘制会盖住右上角开关按钮（点按钮实际点在抽屉上，观感"按钮卡住"）。抽屉与开关按钮的 `Positioned` 顺序是刻意的，别调回去。 |
