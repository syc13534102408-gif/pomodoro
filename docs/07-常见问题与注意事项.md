# 07 常见问题与注意事项（雷区清单）

> 改代码前通读一遍。每条都踩过坑，多数有单测或事故记录。

## 1. 依赖与构建

| # | 雷区 | 说明 |
|---|---|---|
| 1 | `path_provider_android: 2.2.23` override **勿删** | 2.3.x 引入 `jni` 原生模块，CMake 产物写回只读 pub 缓存导致构建失败 |
| 2 | `fl_chart` **禁止重新引入** | 统计图已由 `BrickBars` 自绘， reintroduce 会破坏 05 的架构约定 |
| 3 | `flutter analyze` 会崩 | 本机 LSP 通道崩溃（exit 255），用 `tools/flutter/bin/dart analyze` 代替，效果等价 |
| 4 | 改名/搬目录后构建失败 | `flutter config --android-sdk/--jdk-dir` 与 `android/local.properties` 的 `sdk.dir` 都存绝对路径，必须重设；`settings.gradle.kts` 已改为 UTF-8 读取 `local.properties`（兼容中文路径） |
| 5 | release 用 debug 签名 | 当前 `build.gradle.kts` 显式如此（本地分发），上架商店前需换正式签名 |
| 6 | macOS Release 沙箱必须关闭 | `macos/Runner/Release.entitlements` 中 `com.apple.security.app-sandbox = false`；本地 ad-hoc 签名 + 沙箱会启动即崩（`_libsecinit_appsandbox`） |
| 7 | macOS 新增 Swift 文件不会自动进工程 | 模板用的是显式文件引用，新文件必须手改 `macos/Runner.xcodeproj/project.pbxproj` 四处：`PBXBuildFile`、`PBXFileReference`、Runner group 的 `children`、Runner target 的 `Sources`。改完用 `xcodebuild -project ... -list` 验证能否解析 |
| 8 | 出包后必须**退出旧进程**再打开新包 | App 常驻菜单栏（`applicationShouldTerminateAfterLastWindowClosed = false`），旧进程不退出会一直跑旧代码，表现为"新功能没生效" |

## 2. 逻辑层（改前必读）

| # | 雷区 | 说明 |
|---|---|---|
| 1 | 超时锚点 | `overtimeStartedAt` 必须取 `session.deadline`（计划结束时刻），不是"现在"；改错会让后台经过的时间不计入超时（有单测） |
| 2 | 通知刷新 | 前台通知只在状态切换时更新（`_syncForeground` 的 key 比较），**不要**改回每秒刷新标题——会打断 Chronometer 走表，且进程被冻结时刷新无效 |
| 3 | 通知 id / 频道 | 锁屏倒计时与前台服务共用 id `5150`、频道 `pine_lock_timer`，发布即原地替换，不要拆成两个通知 |
| 4 | 同步指纹 | `cloudFingerprint()` 剔除 `id` 是为了防止"恢复后 id 变化"产生假冲突；改动必须同步更新 `test/cloud_auto_test.dart` |
| 5 | 自动同步前置条件 | 仅在**已绑定同步码**时工作，避免静默创建网页端看不到的孤立备份；勿改成无条件同步 |
| 6 | 长休息判定 | `count % 4 == 0` → longBreak；这是产品规则，不是魔法数字 |
| 7 | 两端同步地址 | 改 `index.html` 的 `DEFAULT_SYNC_URL` 时必须同步改 `pomodoro_app/lib/src/cloud_sync.dart` 的 `CloudSync.defaultBaseUrl` |

## 3. 云端服务

| # | 雷区 | 说明 |
|---|---|---|
| 1 | **不要用 API 网关** | 腾讯云 API 网关已于 2025-06-30 停服；本项目用 SCF「函数 URL」触发器 |
| 2 | 环境变量整体替换 | `deploy.py --update` 会替换全部环境变量，务必带上 `PINE_SECRET_*`（脚本已保证，手动改配置时注意） |
| 3 | `deploy.py` 的 `detach_cls_logs` **勿删** | 否则 SCF 重新挂日志主题 → CLS 按分区持续扣费（曾因此欠费、CLS 停服） |
| 4 | `workers.dev` 国内不可达 | Cloudflare 同步接口国内移动网络不可用（已实测），所以同步迁到腾讯云；但**网页端后台提醒仍依赖 Cloudflare**，国内网络下可能失效 |
| 5 | COS 桶需控制台手动创建 | `tencentcloud-sdk-python-scf` 不含桶管理 API；桶 `pine-sync-1478270344`（ap-guangzhou，私有读写）已存在 |
| 6 | 新旧后端数据不互通 | 腾讯云备份与 Cloudflare 备份是两份独立数据；首次互通流程：网页端上传 → 手机「从云端恢复」输入网页同步码 |

## 4. 设备相关

| # | 事项 | 说明 |
|---|---|---|
| 1 | OPPO/ColorOS 后台冻结 | `OplusHansManager` / `LocationFreezeProc` 会冻结后台进程；锁屏倒计时已用系统 Chronometer 规避，但通知到达仍可能受影响，必要时引导用户加自启动白名单 |
| 2 | 真机型号 | OPPO Find X9 Pro（arm64）；构建命令带 `--target-platform android-arm64` |
| 3 | 首次安装 | 需允许「安装未知应用」；开启提醒后到「后台常驻通知」把应用加入电池优化白名单 |
| 4 | macOS App Nap 会节流计时 | 窗口不可见时系统对定时器做 coalescing，倒计时变慢/跳秒。`AppDelegate` 里 `ProcessInfo.beginActivity(.userInitiated/.latencyCritical)` 的令牌**必须常驻持有**，勿删（已验证：禁用后后台 5 分钟与墙钟一致） |
| 5 | 全屏 App 之上显示悬浮窗靠窗口层级 | `FloatingTimerPanel` 用 `level = .statusBar` + `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`，**已实测可行**；若改为普通 `.floating` 会消失。要盖住更强势的窗口再升到 `.popUpMenu` |
| 6 | 全屏时菜单栏与 Dock 都看不见 | 系统行为，改不了。所以"后台也能看到进度"的能力落在悬浮窗上，菜单栏只作为非全屏场景的补充 |

## 5. 已知限制（不是 bug，不要"顺手修"）

1. **深色模式未设计**：系统深色下 App 仍显示浅色（`ThemeMode.light` 是刻意的）；启动屏已用 `values-night/styles.xml` 统一米黄底避免闪黑。要做深色需单独出一套反相色板。
2. **两端云净荷 schema 不一致**：网页 `tasks/records/history/done`，安卓 `tasks/records/todos/settings/...`，靠"缺省补齐"兼容；根治需统一 schema（工作量大，暂缓）。
3. **macOS 到点提醒未实机验证**：代码路径存在，需系统通知授权后实测。（注：菜单栏/悬浮窗的计时显示已于 2026-09-09 实机验收通过，通知本身仍未验证）
4. **锁屏通知卡片样式不可控**：由系统决定，设计稿中的「积木风通知卡」仅是品牌示意，**不实现**（可控部分只有 small icon）。
5. **网页端测试盲区**：`index.html` 无自动化测试，改动靠人工回归（刷新恢复、同步弹窗、推送）。
