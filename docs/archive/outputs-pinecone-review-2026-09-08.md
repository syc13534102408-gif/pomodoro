# 松果 / 专注时光 —— 系统评估与增强建议(2026-09-08)

> 结合已实现功能(见 docs/01、05、07)与当前代码现状评估。
> 判断原则:优先保护"数据在自己手里"这一核心理念与已修的正确性成果,
> 性能类建议只给有事实依据的,不给无病呻吟的微优化。

## 一、总体判断

项目已进入"功能完整、三端可跑、同步/通知链路闭环"的收尾验收期。当前最大的
风险不是"缺功能",而是三类:
1. **唯一副本风险**:20+ 本地提交未推送远端,代码只在本机;
2. **跨端口径残留**:网页端时间/净荷 schema 与安卓端仍不一致,是已知未闭环项;
3. **人工回归面大**:网页端零自动化测试、安卓真机走查仍靠逐轮反馈(本轮已连报 3 个 UX 问题)。

以下建议按 P0/P1/P2 排布,成本按单人规模粗估。

| # | 建议 | 维度 | 用途 | 价值 / 风险 | 成本 |
|---|---|---|---|---|---|

## 五、明确不建议(防范围蔓延)

- **换 SQLite/数据库化存储**:个人数据量级(百~千条记录)下 SharedPreferences/localStorage + 全量净荷足够,引入 DB 只有负担。
- **实时多端同步(WebSocket/推送式)**:产品定位是"备份与搬运",触发式同步已满足;实时化抬高复杂度且网页端后台不可达(Cloudflare 国内问题)。
- **过早的"增量同步"协议**:在上传/下载全量仍是 ~几十 KB 量级时,增量化的复杂度不划算;等记录量到万级再议。
- **给统计页加 fl_chart 等图表库**:架构红线(docs/07),自绘 BrickBars 已覆盖需求。

## 六、推荐实施顺序

**阶段一(1~3 天,立竿见影)**:P0-1 推送备份 → P0-4 真机走查收口(攒批小修) → P0-2 网页时间对齐 → P2-3 月历空态(顺路)。

**阶段二(1~2 周,正确性与体验加固)**:P1-1 计时页重建隔离 → P1-3 自动备份增强 → P1-4 macOS 收尾 → P1-2 的"对照矩阵 + merge 单测"先行件。

**阶段三(按需,择高性价比做)**:P1-5 网页 smoke、P2-1/P2-2 历史浏览与导出(可提前)、P2-5/P2-6 同步安全与合并、P2-8 深色立项(需拍板)。

> 注:未验证项已如实标注(如 P1-1 的耗电改善、P2-7 的体积收益),
> 实施前建议先做小样本测量再投入。

## 七、口径收窄:若暂时只关注安卓端

剔除跨端项(网页时间对齐、schema 统一、网页 smoke、macOS 收尾)后,安卓单端的
优先级重排如下(新增 3 项安卓特有建议,标 ★):

**P0 — 安卓必要(近期)**
1. 代码推送备份(工程卫生,不随平台变化)。
2. ★ **修复本机 flutter test 通道**:33 个单测(含新增回归)目前因
   `flutter_tester` WebSocket 握手失败全部跑不了,测试资产闲置、每轮只能靠
   `dart analyze` 兜底;先排查本机 flutter 工具链原因(常见:SDK cache 损坏、
   dart/flutter 版本错位),恢复后验收自动化才算闭环。
3. ★ **全局错误兜底**:`main.dart` 无 `runZonedGuarded`/`FlutterError.onError`,
   崩溃即闪退且无痕迹;加全局捕获落本地日志(设置页可见或下次启动提示),
   真机问题可回溯(尤其是 ColorOS 冻结/后台场景)。
4. APK 签名决策(同 P0-3)。
5. 真机走查收口(同 P0-4)。

**P1 — 安卓强烈建议(中期)**
1. 计时页每秒重建隔离(同 P1-1,安卓耗电/流畅直接相关)。
2. 自动备份增强(同 P1-3:节流自动上传 + 设置页显示"最近备份时间/摘要" +
   本地轮转备份)。
3. ★ **净荷往返与容错单测加固**:不依赖网页端配合,先把安卓侧
   `toMap/fromMap`、脏数据回退、`dateKey/at` 双口径的边界全部固化成单测
   (现有 roundtrip 已覆盖一部分),防止未来任何一端数据格式变化把安卓打挂。
4. 小 UX 批次:月历空态(P2-3)+ 详情时间区间(P2-4),可并入走查攒批修。

**P2 — 安卓可选**
1. 历史统计:月历翻月 + 点日明细(安卓报告页)。
2. 数据导出 JSON/CSV(安卓分享面板)。
3. ★ 首次开启提醒时引导加入电池优化白名单(ColorOS 冻结是已知雷区,
   文档引导不如应用内一次引导)。
4. 409 冲突记录级合并(同 P2-6)。
5. R8 minify/shrinkResources 缩包(同 P2-7,需全量构建+真机冒烟)。
6. 同步码可作废/警示(同 P2-5,安卓设置页入口)。
7. 深色模式:默认不做(既有产品决策,要改需单独立项)。

**安卓单端建议顺序**:
推送备份 → 修好 flutter test 通道(让后续每步有回归兜底)→ 真机走查 + 小 UX 批
→ 崩溃兜底 → 计时页重建隔离 → 备份增强/可见 → 净荷容错单测 → 历史统计/导出
等 P2。
