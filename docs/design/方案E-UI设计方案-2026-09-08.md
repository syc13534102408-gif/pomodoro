## 2. 设计目标与通用原则

设计目标一句话：**让「专注时光」看起来像一本安静、可信、越用越有积累感的手帐，而不是一台计时仪表。**

通用原则（与视觉方向解耦，方向无论选 A/B/C 都成立）：

| # | 原则 | 说明 |
|---|---|---|
| G1 | 一屏一事 | 计时主屏只回答一个问题：「现在到几点了」；把清单、记录等上下文收敛为可折叠组或二级层 |
| G2 | 用留白与纸色分层，不靠描边网格 | 卡片边界用明度差 + 柔和投影表达（推翻 D 的墨边体系） |
| G3 | 阶段色只做「状态语义」，不做大面积底 | 专注红/短休绿/长休金 的**语义映射保留**（用户已建立认知，不推翻），但以小面积出现：色条、进度、色点、印章 |
| G4 | 数字恒等宽 | 计时/时长/百分比一律 mono + `tabularFigures`，秒跳不抖版（**从 D 继承的通用规则**） |
| G5 | 情感化反馈只在「完成」时刻 | 平时克制，完成时给一次明确的庆祝微动效（见 §6.2） |
| G6 | 无障碍底线 | 触摸 ≥44dp；正文对比 ≥4.5:1；尊重「减弱动画」；文字缩放不破版（**从 D 继承**） |
| G7 | 只改表现层 | `engine/models/storage/cloud_*/notifications/menu_bar_timer` 逻辑一律不动；新增只读数据需求须先确认（见 D2） |

从方案 D **继承的通用项**（非其视觉专属，属普适规则，不算「沿用旧风格」）：tabular 数字、44dp 触摸目标、减弱动画全局归零、危险操作红色语义 + 确认框、阶段色语义映射、`flutter test` 回归纪律、不引第三方图表库、不新增第三方依赖。

## 3. 视觉方向提案（决策 D0）

三个方向都满足 G1–G7；差异在「气质」。**推荐 A**，理由见 3.1 末尾。

### 3.1 方向 A：松林手帐（推荐，主推全规格）

- **概念**：一本暖纸手帐。米色纸面 + 白纸卡片 + 松绿点缀；卡片像贴上去的便签，圆角柔和、投影很浅；阶段色是手帐里的「彩铅/印章」，只用在小面积。记录、清单、统计全都用「纸张语言」表达：打卡格子、勾选、完成章。
- **气质关键词**：安静 / 可信 / 有积累感 / 低刺激。
- **为什么适合本产品**：① 品牌即「松果」，纸张-森林天然同源，不是硬贴；② 产品哲学「到点不自动结束、不施压」要求 UI 低压迫感，柔纸方向与之一致；③ 手帐天然具备「记录/回顾」叙事，能同时救活 P5（报告页叙事）与 P2（记录详情）；④ 与方案 D 的喧闹粗边形成最大差异化，满足「推翻重来」的诉求。
- **成本**：中。无需新字体（中文字体用系统，标题用字重+留白实现）；纸纹建议 1 张可平铺 PNG（约 10–20KB），动效全用 Flutter 内置能力。

### 3.2 备选方向（简表，选定后才展开全规格）

| 方向 | 概念 | 优点 | 代价/风险 |
|---|---|---|---|
| B 深夜森林 | 深色优先：松墨黑底、大号低亮度数字、阶段色只做微光 | 夜间沉浸强、护眼；与「专注」场景贴合 | 白天观感弱；与锁屏/系统通知观感割裂；浅色仍需一套，成本双倍 |
| C 留白极简 | 白底黑字排版驱动，颜色仅存 3 个阶段点 | 成本最低、跨端最稳、无障碍最省心 | 差异化弱，易显「工具味」；对 P4（情感化）帮助有限 |

### 3.3 决策后的连锁影响

- 选 A：直接采用 §4–§10 的完整规格（本文后续均按 A 展开）。
- 选 B/C：§7 令牌、§3 视觉细则需重写；§4 信息架构、§5 页面结构、§6 交互流程、§8/§9 技术方案**大部分可直接复用**（本文刻意把架构层与视觉层解耦，目的就在于此）。

```
└──────────────────────────────────────────────────────────────────┘
```

### 4.2 为什么引入底部导航（D1 论证）

| 现状问题 | 底部导航后 |
|---|---|
| 首页顶栏塞「统计/设置」两个图标入口，导航藏得深 | 三主域一次可见，拇指可达 |
| 报告/设置无独立「页感」，像被 push 出来的附属 | 三个平级 Tab，心智模型 = 「计时 / 回顾 / 管理」 |
| —— | 代价：竖向空间被占 ~80dp → 用「今日/最近可折叠 + 紧凑模式」回收（见 §5.1） |

若 D1 选「否」（保守，保持 push 导航）：本节其余内容不变，仅把 Tab 壳替换回顶栏图标 + push，代价是 P1 只缓解一半。

### 4.3 层级规则

- **L0 主屏**：专注页一屏一事；报告/设置各自一屏。
- **L1 任务上下文**（不打断计时主循环）：事件管理、清单、补记、记录详情 —— 一律 bottom sheet 呈现，从主屏呼出。
- **L2 危险确认**：对话框，绝不用 sheet 或直接执行。

## 5. 核心功能模块与主要页面设计思路

### 5.1 专注页（Tab1 / home，安卓竖屏）

布局结构树（目标态；间距均以 8dp 网格为基准）：

```
Scaffold(纸面)
└ NavigationBar(3 Tab)
└ SafeArea → Padding(h20)
   └ Column(stretch)
      ├ 日期行 H≈36          // 「9月8日 周二」15/sub，左；右侧松果 mark 16px（品牌弱化，不抢戏）
      ├ gap 8
      ├ PhaseSegments H48     // 专注/短休/长休 三段；选中=阶段色浅底(α0.14)+实心色点+深色字
      ├ gap 14
      ├ 任务便签 H56(卡片)    // [阶段色圆点] 任务名 15（空态：“选择专注事件…”sub） [›]
      ├ gap 14
      ├ Expanded
      │  └ TimerPaper         // 见下：顶部 6px 色条 + caption + 大 mono 时钟 + 细进度
      ├ gap 14
      ├ 控制行 H48
      │   ├ 重置：文字按钮(sub)  或 40×40 图标（P5 决策点）
      │   ├ 主按钮 Expanded：开始/暂停/继续（阶段色实底，白字，胶囊）
      │   └ 完成：仅 运行/超时 态出现（金纸底金边金字 或 金色实底墨字——见状态表）
      ├ gap 14
      ├ 「今日」组（卡片，可整组折叠）
      │   ├ 头行：「今日 2/4」15/w600 + 迷你打卡格（最多显示 8 格，超出显示 +N）
      │   └ 清单预览 ≤3 行：[纸面勾选格] 任务文字（完成=划线+sub）  全览→打开清单 sheet
      ├ gap 12
      └ 「最近记录」组（卡片，默认折叠收进 3 行）
          ├ 头行：「最近记录」+ 右侧「补记 +」
          └ 行(可点→记录详情 sheet)：10px 阶段/任务色点 + 任务名 14 + 时长 mono + 时刻 11/sub
```

TimerPaper 主卡规格（方向 A）：

| 元素 | 规格 |
|---|---|
| 卡片 | 白纸 card 底、圆角 20、浅投影；内部不铺阶段色 |
| 顶部色条 | 6px 高、圆角 3，颜色=当前阶段色（阶段切换 300ms 过渡） |
| caption 行 | 12 号：阶段色小圆点 + 状态文案（五态文案见 §6.1） |
| 时钟 | mono w600，字号 = 卡宽 × 0.28，clamp(40, 88)，`FittedBox` 防溢出；墨色正文 |
| 进度 | 细进度条 6px（轨道 = line 色 α0.4，填充 = 阶段色），或按目标显示「打卡格」（D2 微决策） |
| 空态 | 首次使用且无任何记录时，卡内放一句纸面引导文案 + 「先去建个事件」按钮（→ 事件 sheet） |

五态视觉对照（对比方案 D 的「整卡换底」，改为「色条+文案+按钮」三处表达）：

| 状态 | 色条 | 时钟 | caption | 控制行 |
|---|---|---|---|---|
| 空闲 | 当前阶段色 | 计划时长 MM:SS | 阶段名 · 任务名 | 主按钮「开始」（阶段色实底） |
| 运行 | 阶段色 | 剩余 MM:SS（等宽防抖） | 第 N 个番茄 · 任务名 | 主按钮「暂停」（墨色实底白字）+ 出现「完成」 |
| 暂停 | 阶段色 α0.5 | 冻结剩余 | 前缀「已暂停」 | 主按钮「继续」 |
| 休息 | 短休/长休色 | 剩余 MM:SS | 休息提示（见文案基调） | 主按钮「跳过休息」？→ 保守：保持现有逻辑的「开始/暂停」 |
| 超时 | 金 | +MM:SS（金字） | 「已超时 · 仍在本轮累积」 | 主按钮变「完成本轮」（金实底），不自动结束（产品红线） |

> 注：休息/超时态的控制行最终以现有 engine 暴露的能力为准，实施前核对 `home_page` 现有五态分支，不新增逻辑。

### 5.4 二级层（sheets 族）与记录详情（D2）

统一 PaperSheet 规格：圆角 24、顶部 48×4 圆角把手（line 色）、纸面底、列表行 hairline 分隔；危险/删除按钮一律红语义。

| Sheet | 要点 |
|---|---|
| 专注事件管理 | 行=任务色点+名+编辑/删除；选中态=整行浅 tint + 左侧 3px 阶段色条（替代方案 D 的 gold 整块）；新增/编辑对话框含 8 色板 |

| **记录详情（新增）** | 只读展示一条 `FocusRecord`：任务、阶段、起止时间、时长、状态徽章（completed/manual/paused/interrupted 各配徽章色+文案）；底部「删除这条记录」（红）+ 确认。数据仅读 storage 现有记录 |

## 6. 关键交互流程（决策 D2/D4 相关项已标注）

### 6.1 计时主循环（核心流程）

```
进入专注页
 └ 空闲：选任务 → 主按钮「开始」
    └ 运行（前台服务倒计时，锁屏可看）
       ├ 点「暂停」→ 暂停（时钟冻结、caption 标注）
       ├ 点「完成」（或超时后「完成本轮」）→ 完成章动画 + 落一条 FocusRecord + 今日格子 +1
       └ 倒计时归零 → 进入休息阶段（到点不自动结束：若用户在专注态未操作，继续 +MM:SS 累积）
```

| 触发 | 反馈（方向 A） | 动画 |
|---|---|---|
| 按压任意纸面控件 | 卡片 scale 0.97 + 投影收敛（「纸被轻按」） | 160ms easeOutCubic |
| 阶段切换 | 色条颜色过渡 + Segments 选中态迁移 | 300ms |
| 完成一次专注 | **完成章**：便签角盖一枚「done」章（弹性 pop），今日打卡格跳一下填色；落库后「最近记录」插入新行 | 260ms elasticOut |
| 到点 | 轻提示（沿用现有通知逻辑），UI 进入超时态显示 +MM:SS | 无强打断 |
| 清单勾选 | 纸面格变色 + 文字划线 180ms | 180ms + 3° 旋转 |
| 减弱动画开启 | 以上全部时长归零，状态直切 | 0ms |

### 6.2 二级流程（文字步骤化）

- **补记**：最近记录组头「+」→ sheet（选事件 → 填时长 → 选时间）→「添加完成记录」→ 落 `manual` 记录 → 行插入 + SnackBar「已补记」。
- **事件增删改**：任务便签点击 / 事件管理 sheet → 编辑弹窗（名称 + 8 色板，选中圆点外圈松绿环）→ 保存。删除事件前置确认（删除后其历史记录保留，仅失去颜色映射 —— 以现有 storage 行为为准）。
- **云同步**：设置 →「上传本机数据」→ 完成 SnackBar；「从云端恢复」→ 确认框（提示将覆盖本机）→ 成功后重载页面数据（逻辑复用现有接口）。
- **清空数据**：红字入口 → 对话框 1（说明后果）→ 对话框 2 确认 → 完成。两级确认沿用现有对话框机制，只换视觉。
- **Tab 切换**：专注/报告/设置瞬时切换（可选 120ms 纸面淡入，D4 微决策；默认不做，节省开销）。

## 8. UI 实现技术选型

| 决策点 | 选型 | 理由 |
|---|---|---|
| 主题承载 | 静态 token 类（`PineTheme` v2，含 `light/dark` 两套字段）+ 现有 `buildPineTheme()` 扩展 | 与现有 `theme.dart` 结构一致、可静态测试；`ThemeExtension` 可选做，默认不引入复杂度 |
| 深浅主题 | 仅浅色（默认）；夜间纸为 D3 可选项 | 锁屏/系统通知不可控，深浅不一致是主要顾虑；若做，`themeMode` 走 `ThemeMode.system`，纯 UI 层改动 |
| 图表 | `CustomPaint` 自绘（堆叠圆角柱 / 月历格） | 与方案 D 相同的纪律：不引入 fl_chart，逻辑零依赖 |
| 动画 | Flutter 内置 `TweenAnimationBuilder` / `AnimationController`；不引 Rive/Lottie | 完成章/勾选均为矢量小动效，内置足够；零新增体积 |
| 纸纹 | 1 张 256px 可平铺噪点 PNG 入 assets（约 10–20KB）；或 CustomPaint 程序化噪点 | 二选一，**需实现阶段真机验证**（性能/观感，未验证项），默认走 assets |
| 图标 | Material Icons 为主 + 少量自绘（松果 mark、完成章图形） | 成本最低；app 图标走 Android adaptive icon 资源层 |
| 依赖变更 | **0 新增**（除 D3 夜间纸亦无需新依赖） | 红线：工程依赖只减不增 |
| 测试策略 | 沿用 widget test 纪律；组件库阶段加临时 demo 页逐个挂载验证 | 每阶段保持 `flutter test` 全绿 |

### 12.2 数据可行性核实结论（依据 `lib/src/models.dart` / `storage.dart` 实读，非推测）

| 项 | 结论 |
|---|---|
| 月历格数据 | `AppData.records` 为**全量** `List<FocusRecord>` 常驻内存；按 `dayKey`(`YYYY-MM-DD`) 与 `at` 做按日聚合属**纯 UI 只读**，无需新增逻辑接口 |
| 记录详情 | `FocusRecord` 含 `taskName / minutes(double) / status / at / dayKey / completedFlag`，可直接渲染；删除复用现有记录删除逻辑 |
| 今日目标单位 | **今日目标按专注分钟计**（`goalMinutes`，默认 200）；周目标按**次**计（`weekGoal`，默认 20）——设置页文案为「今日目标（分钟）」「本周目标（次）」 |
| 统计口径 | 「次」的计数沿用现有 stats 聚合口径（`counted = status.counted || completedFlag`），不另起新口径 |

### 12.3 勘误与视觉微调（R1–R4，实施与视觉稿一律以此为准）
